# 07. Система логирования

## Обзор

VRXX генерирует большой объем диагностических данных от графического интерфейса, демона и внутреннего ядра (Sing-box). Чтобы не замедлять работу приложения и предотвратить износ SSD-накопителей, система логирования спроектирована асинхронной, буферизованной и разделенной на отдельные потоки.

Для логирования используется экосистема крейта `tracing`.

## Потоки логов

Все логи сохраняются в директорию `~/.local/share/vrxx/logs/` (согласно стандарту XDG Data). Лог-файлы подвергаются автоматической ротации (`tracing_appender::rolling::daily`).

| Файл | Содержимое | Описание |
| --- | --- | --- |
| `app.log.YYYY-MM-DD` | GUI Logs | Ежедневный журнал графического интерфейса. Создается, если программа запущена без аргумента `--daemon`. |
| `daemon.log.YYYY-MM-DD` | Daemon Logs | Ежедневный журнал системного демона. Создается, если программа запущена с `--daemon`. |
| `all.log.YYYY-MM-DD` | Combined Logs | Ежедневный объединенный поток всех событий. |

## Самовосстановление сети (Self-Healing)

При каждом запуске системного демона `vrxx-daemon` автоматически выполняется процедура самовосстановления сети `network::self_heal()` (`src/daemon/network.rs`):
1. **Очистка сиротских TUN-интерфейсов**: Обнаружение и удаление подвисших сетевых интерфейсов `vrxx-tun`.
2. **Очистка правил маршрутизации**: Сброс зависших правил таблицы маршрутизации (`ip rule del table 100`).
3. **Восстановление GNOME Proxy**: Если демон не подключен к VPN, выполняется проверка `org.gnome.system.proxy mode` и при необходимости сброс в режим `"none"`.

## Обработка критических ошибок и AdwAlertDialog

В случае критических сбоев подключения к VPN пользователю выводится адаптированный диалог `AdwAlertDialog` (`src/ui/error_dialog.rs`):
- **Человекочитаемые сообщения**: Ошибки форматируются с использованием `gettext` локализации.
- **Скопировать технический лог**: Кнопка «Скопировать технический лог» помещает полный стек ошибки и текущие диагностические данные в системный буфер обмена (`GdkClipboard`).

## Архитектура логирования (Tracing Stack)

В коде используются макросы `trace!`, `debug!`, `info!`, `warn!`, `error!` вместо обычного `println!`.
Вызовы `println!` и `eprintln!` полностью запрещены в проекте.

Архитектура:
1. **Подписчик (tracing-subscriber)** с форматом (`fmt::Layer`), который пишет в файл без ANSI-цветов.
2. **Аппендер (tracing-appender)** использует `non_blocking` обертку с ежедневной ротацией `tracing_appender::rolling::daily`.
3. **MultiWriter (кастомная реализация)**: дублирует сообщения в специфичный лог (например, `app.log`) и в общий лог (`all.log`).
4. **GLib Redirect**: Перехват внутренних логов GLib/GTK и перевод их в `tracing`.

## SSE Tracing Layer и Локальный UI Tracing Hook (Живые логи в UI)

Для отображения системных и приложенческих логов без задержек и без дискового ввода-вывода используются два взаимодополняющих механизма Tracing:

1. **`ConsoleUiTracingLayer` и `UiLogBroadcaster`** (`src/logger.rs`):
   - Перехватывает все события логирования графического интерфейса (`tracing::info!`, `warn!`, `error!`, `debug!`), фоновых сервисов (пинг, автообновление GeoIP) и перенаправленных системных логов GLib/GTK.
   - Сохраняет недавние записи в потокобезопасном кольцевом буфере в оперативной памяти (`MAX_UI_LOG_HISTORY` = 1000 записей).
   - Рассылает новые события в реальном времени через асинхронный широковещательный канал `tokio::sync::broadcast`.
   - Позволяет мгновенно отобразить актуальные логи при открытии окна без необходимости подключения демона.

2. **`SseTracingLayer`** (`src/daemon/events.rs`):
   - Активен в режиме системного демона (`--daemon`).
   - Перехватывает события ядра sing-box и фонового сетевого демона, передавая их клиентам через Server-Sent Events (`/api/events`).

## EventManager и кольцевой буфер демона

`EventManager` (`src/daemon/events.rs`) отвечает за рассылку событий со стороны привилегированного процесса `vrxx-daemon`.
Он использует `tokio::sync::broadcast::channel` с емкостью 1024 сообщения. Подключенный клиент (GUI) получает события ядра и сетевые логи мгновенно по SSE.

Кроме того, EventManager содержит кольцевой буфер `VecDeque` на 1024 элемента. При подключении нового клиента окно логов может запросить `/api/history`, чтобы получить недавние сетевые события.

## Окно логов (Virtual Console / Log Window)

В пользовательском интерфейсе реализована полноценная виртуальная консоль (`src/ui/components/log_window.rs`, `src/ui/components/log_window.ui`):
Она объединяет локальные консольные логи приложения из Tracing и сетевые события ядра sing-box из SSE в единый интерактивный терминал.

### Возможности виртуальной консоли:
- **Строгий режим Read-Only**: Текстовое поле настроено с `editable = false` и `cursor_visible = false`, что исключает случайное редактирование при сохранении удобного выделения текста.
- **Цветовая подсветка по формату (Color Tokenization)**:
  - **Таймстамп**: Приглушенный нейтрально-серый цвет (`#77767B`) для сохранения фокуса на сообщении.
  - **Уровень логирования (Level Badge)**: Яркие акцентные цвета — красный жирный (`#E01B24`) для `ERROR`/`FATAL`, янтарный жирный (`#E5A50A`) для `WARN`, синий жирный (`#3584E4`) для `INFO`, фиолетовый (`#9141AC`) для `DEBUG`.
  - **Модуль/Таргет**: Выделение компонента в квадратных скобках (например, `[vrxx::ui]`, `[sing_box]`, `[TCP]`) бирюзово-зеленым стилем (`#2EC27E`).
  - **Тело сообщения**: Читаемый контрастный шрифт с подсветкой ошибок и сетевых переходов (`->`).
  - **Очистка ANSI-кодов**: Автоматическое удаление служебных управляющих escape-последовательностей терминала (`\x1B[...]`).
- **Двухуровневая фильтрация**:
  - *По источнику*: Все логи, Ядро sing-box, Приложение GUI, Трафик / Access.
  - *По уровню критичности*: Все уровни, Ошибки (Error), Предупреждения (Warning), Информация (Info), Отладка (Debug).
- **Сортировка по степени важности (Severity Sorting)**:
  - *Хронологический режим*: Порядок поступления событий во времени.
  - *Сортировка по критичности*: Ошибки и сбои выводятся первыми (`ERROR` -> `WARN` -> `INFO` -> `DEBUG`).
  - *Сортировка в обратном порядке (Newest First)*: Свежие события выводятся в самом верху виртуальной консоли.
- **Очистка старых и неактуальных логов**:
  - Кнопка «Очистить логи» и пункт контекстного меню мгновенно очищают виртуальную консоль, сбрасывают буфер в оперативной памяти (`clear_ui_log_history()`) и запускают ротацию и очистку устаревших лог-файлов на диске (`cleanup_old_logs()`).
  - Автоматическая ротация при превышении 1000 строк предотвращает утечки оперативной памяти и замедление GTK.
- **Поиск по тексту (Ctrl+F)**: Мгновенная регистронезависимая подсветка и фильтрация строк.
- **Регулировка масштаба (Zoom)**: Горячие клавиши `Ctrl++`, `Ctrl+-`, `Ctrl+0` и `Ctrl+Колесо мыши` (10%–320%).
- **Экспорт и копирование**: Сохранение в текстовый файл (`Ctrl+S`) и копирование в системный буфер обмена `GdkClipboard`.

## Настройка уровня логирования и Hot Reload

Уровень логирования задается пользователем в Настройках приложения (поле `log_level` структуры `AppSettings`).
Возможные значения: `error`, `warn`, `info`, `debug`, `trace`.

В версии **26.1.0-beta.3** реализован отраслевой стандарт Enterprise Tracing (`src/logger.rs`):
1. **Динамическая перезагрузка (Hot Reload)**:
   - Использование `tracing_subscriber::reload::Handle<EnvFilter, Registry>`.
   - При изменении уровня логирования в GUI Настройках (`settings_page.rs`) вызывается `crate::logger::update_log_level(&level)`.
   - Уровень логирования применяется **мгновенно на лету** без необходимости перезапуска приложения или демона.
2. **Маскирование персональных данных (PII & Secret Sanitization)**:
   - Функция `logger::mask_secret(s: &str) -> String` маскирует пароли, UUID, приватные ключи и токены авторизации (отображаются первые 4 и последние 2 символа, например: `1111****55`).
   - Исключает случайную утечку ключей шифрования в системные журналы.
3. **Политика ротации и удержания (Retention Policy)**:
   - Автоматическая ротация лог-файлов по дням и достижению лимита 10MB.
   - Фоновая функция `cleanup_old_logs()` удаляет файлы старше 7 дней и ограничивает общий размер каталога логов 50MB.

Этот же уровень передается в конфигурацию Sing-box в блоке:
```json
"log": {
    "level": "info",
    "timestamp": true
}
```

## Диагностика

Если что-то не работает (например, VPN не подключается):
1. Выводится диалоговое окно `AdwAlertDialog` с кнопкой «Скопировать технический лог».
2. Скопированный стек содержит время, форматированную причину и детальный трейс.
3. Лог-файлы доступны в `~/.local/share/vrxx/logs/all.log.YYYY-MM-DD`.
