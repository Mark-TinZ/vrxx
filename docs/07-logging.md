# 07. Система логирования

## Обзор

VRXX генерирует большой объем диагностических данных от графического интерфейса, демона и внутреннего ядра (Sing-box). Чтобы не замедлять работу приложения и предотвратить износ SSD-накопителей, система логирования спроектирована асинхронной, буферизованной и разделенной на отдельные потоки.

Для логирования используется экосистема крейта `tracing`.

## Потоки логов

Все логи сохраняются в директорию `~/.local/share/vrxx/logs/` (согласно стандарту XDG Data). Лог-файлы подвергаются автоматической ротации (`tracing_appender::rolling::daily`).

| Файл | Содержимое | Описание |
| --- | --- | --- |
| `app.log.YYYY-MM-DD` | GUI Logs | Ежедневный журнал графического интерфейса. Создается, если программа запущена без аргумента `--daemon`. |
| `daemon.log.YYYY-MM-DD` | Daemon Logs | Ежедневный журнал системного демона. Создается, если программа запущена с `--daemon`. |
| `all.log.YYYY-MM-DD` | Combined Logs | Ежедневный объединенный поток всех событий. |

## Самовосстановление сети (Self-Healing)

При каждом запуске системного демона `vrxx-daemon` автоматически выполняется процедура самовосстановления сети `network::self_heal()` (`src/daemon/network.rs`):
1. **Очистка сиротских TUN-интерфейсов**: Обнаружение и удаление подвисших сетевых интерфейсов `vrxx-tun`.
2. **Очистка правил маршрутизации**: Сброс зависших правил таблицы маршрутизации (`ip rule del table 100`).
3. **Восстановление GNOME Proxy**: Если демон не подключен к VPN, выполняется проверка `org.gnome.system.proxy mode` и при необходимости сброс в режим `"none"`.

## Обработка критических ошибок и AdwAlertDialog

В случае критических сбоев подключения к VPN пользователю выводится адаптированный диалог `AdwAlertDialog` (`src/ui/error_dialog.rs`):
- **Человекочитаемые сообщения**: Ошибки форматируются с использованием `gettext` локализации.
- **Скопировать технический лог**: Кнопка «Скопировать технический лог» помещает полный стек ошибки и текущие диагностические данные в системный буфер обмена (`GdkClipboard`).

## Архитектура логирования (Tracing Stack)

В коде используются макросы `trace!`, `debug!`, `info!`, `warn!`, `error!` вместо обычного `println!`.
Вызовы `println!` и `eprintln!` полностью запрещены в проекте.

Архитектура:
1. **Подписчик (tracing-subscriber)** с форматом (`fmt::Layer`), который пишет в файл без ANSI-цветов.
2. **Аппендер (tracing-appender)** использует `non_blocking` обертку с ежедневной ротацией `tracing_appender::rolling::daily`.
3. **MultiWriter (кастомная реализация)**: дублирует сообщения в специфичный лог (например, `app.log`) и в общий лог (`all.log`).
4. **GLib Redirect**: Перехват внутренних логов GLib/GTK и перевод их в `tracing`.

## SSE Tracing Layer (Живые логи в UI)

Самая сложная часть — как передать системные логи от привилегированного демона (работающего от root) в графический интерфейс без постоянного чтения файла.

Решение: Кастомный слой трассировки `SseTracingLayer`.
Этот слой активен только в режиме `--daemon`. Он перехватывает **каждое** лог-событие в приложении, извлекает текст сообщения через `MessageVisitor` и отправляет его в EventManager.

## EventManager и кольцевой буфер

`EventManager` (`src/daemon/events.rs`) отвечает за рассылку событий.
Он использует `tokio::sync::broadcast::channel` с емкостью 1024 сообщения. Любой подключенный к демону клиент (GUI) получает эти сообщения мгновенно по SSE.

Кроме того, EventManager содержит `VecDeque` (кольцевой буфер) на те же 1024 элемента. При подключении нового клиента (открытии окна логов), он может запросить `/api/history`, чтобы мгновенно получить последние события, не обращаясь к диску.

## Окно логов (Log Window)

В пользовательском интерфейсе есть отдельное окно логов (`src/ui/components/log_window.rs`).
Оно выполняет две функции:
1. Читает последние события из файлов на диске (история).
2. Подписывается на `/api/events` (SSE-поток) через `DaemonClient`. Получаемые события немедленно вставляются в текстовое поле `gtk::TextView`.

Возможности окна:
- **Фильтрация**: Показ только Error/Warn/Info (кнопки вверху).
- **Автоскроллинг**: При поступлении новых сообщений текстовое поле прокручивается вниз.
- **Очистка**: Удаление логов из UI.

## Настройка уровня логирования

Уровень логирования задается пользователем в Настройках приложения (поле `log_level` структуры `AppSettings`).
Возможные значения (от самого тихого к самому шумному): `error`, `warn`, `info`, `debug`, `trace`.

Этот же уровень передается в конфигурацию Sing-box в блоке:
```json
"log": {
    "level": "info",
    "timestamp": true
}
```

## Диагностика

Если что-то не работает (например, VPN не подключается):
1. Выводится диалоговое окно `AdwAlertDialog` с кнопкой «Скопировать технический лог».
2. Скопированный стек содержит время, форматированную причину и детальный трейс.
3. Лог-файлы доступны в `~/.local/share/vrxx/logs/all.log.YYYY-MM-DD`.
