# 06. Настройки приложения и безопасное хранилище ключей

## Обзор

Конфигурация VRXX разделена на два независимых хранилища:
1. **`~/.config/vrxx/settings.json`** — открытый JSON-файл общих настроек приложения (тема, язык, порты, параметры DNS, правила маршрутизации, белые списки).
2. **`~/.config/vrxx/data.dat`** — защищенный зашифрованный бинарный контейнер со списком VPN-профилей и секретных ключей (Host-Bound Encryption AES-256-GCM).

Управление конфигурацией выполняется через структуру `AppSettings` и объект `SettingsManager` (`src/settings.rs`), а криптографические операции — через подсистему `crate::crypto::keystore` (`src/crypto/keystore.rs`).

---

## SettingsManager и жизненный цикл данных

`SettingsManager` отвечает за жизненный цикл обоих файлов:
1. **Инициализация**: При старте проверяется наличие директории `~/.config/vrxx/` (создается при необходимости).
2. **Автоматическая миграция**: Если файл `data.dat` отсутствует, но в старом `settings.json` обнаружен открытый массив `keys`, они автоматически шифруются и переносятся в `data.dat`, а из открытого `settings.json` удаляются.
3. **Загрузка (load)**:
   - Читает параметры интерфейса и сети из `settings.json` (с fallback на `settings.json.bak`).
   - Расшифровывает список профилей из `data.dat` через `keystore::decrypt_keys` (с fallback на `data.dat.bak`).
   - Объединяет их в структуру `AppSettings`.
4. **Сохранение (save)**:
   - Сохраняет настройки в `settings.json` (поле `keys` пропускается благодаря `#[serde(skip)]`).
   - Сохраняет профили в `data.dat` в зашифрованном виде.
   - Обе записи выполняются **атомарно** (через временные файлы `.tmp` с вызовом `sync_all()`, заменой целевого файла и обновлением `.bak` копий) и со строгими правами `0600` (`-rw-------`).

## Архитектура защиты ключей (Host-Bound Keystore)

Для защиты чувствительных данных (URL-адреса, пароли, UUID, приватные ключи WireGuard) используется привязка к хосту:

1. **Источник энтропии**: Системный 128-битный UUID `/etc/machine-id` (с fallback на `/var/lib/dbus/machine-id`). Этот идентификатор доступен без root-прав (`0444`), сохраняется при всех перезагрузках и обновлениях ядра/дистрибутива, но меняется при чистой переустановке ОС.
2. **Деривация ключа**:
   - `PRK = HMAC-SHA256(APP_UNIQUE_ID, machine_id)`
   - `KEY = HKDF-SHA256(Salt, PRK, info: "vrxx-aes-256-gcm-data-key")`
   - На выходе формируется 256-битный симметричный ключ.
3. **Шифрование контейнера `data.dat`**:
   - Формат контейнера: `VRXXDAT1` (8 байт) + `Nonce` (12 байт из `OsRng`) + `Ciphertext` + `Auth Tag` (16 байт).
   - Алгоритм: **AES-256-GCM** (аутентифицированное шифрование с защитой от подделки и повреждения данных).

## Экспорт и импорт конфигурации (`ExportBundle`)

При экспорте конфигурации через меню программы пользователю открывается интерактивный диалог с независимыми чекбоксами:
- **Настройки приложения** (по умолчанию **включено**).
- **VPN-профили и ключи** (по умолчанию **выключено** с предупреждением о конфиденциальности).

Экспортируемый файл представляет собой JSON-контейнер `ExportBundle`:
```json
{
  "version": 1,
  "settings": { ... },
  "keys": [ ... ]
}
```

При импорте VRXX автоматически определяет структуру файла: настройки сохраняются в `settings.json`, а ключи немедленно шифруются под `machine-id` текущей системы и сохраняются в `data.dat`. Также полностью поддерживается импорт старых файлов `settings.json`.

## Канал перезапуска ядра (Core Restart Channel)

Некоторые изменения настроек (например, переключение тумблера `tun_mode` или смена порта) требуют полного перезапуска процесса Sing-box, чтобы они вступили в силу.

Для этого в `src/settings.rs` реализован глобальный канал `core_restart_channel()`, использующий паттерн `OnceLock` и `async_channel`. Если настройка, требующая перезапуска, меняется, UI-код отправляет сигнал в этот канал, и ядро автоматически рестартует (если оно было включено).

## Системный прокси GNOME

Функция `update_system_proxy(enable: bool, http_port: u16, socks_port: u16)` модифицирует D-Bus хранилище настроек (GSettings) рабочего стола GNOME.
- Если `enable = true`, в `org.gnome.system.proxy` устанавливается режим `manual`, и прописываются порты `127.0.0.1`.
- Если `enable = false`, устанавливается режим `none`.
