# 06. Настройки приложения

## Обзор

Все пользовательские настройки, добавленные VPN-ключи и правила маршрутизации сохраняются в одном файле `~/.config/vrxx/settings.json`.
Управление настройками выполняется через структуру `AppSettings` и объект `SettingsManager` (находится в `src/settings.rs`).

## SettingsManager

`SettingsManager` отвечает за жизненный цикл файла настроек:
1. **Инициализация**: При старте проверяется наличие директории `~/.config/vrxx/` (создается при необходимости).
2. **Загрузка (load)**: Читает JSON-файл. Если файл отсутствует или поврежден, возвращается экземпляр `AppSettings::default()`. 
3. **Сохранение (save)**: Сериализует структуру в JSON. Чтобы не блокировать UI-поток при записи на диск, сохранение выполняется в отдельном фоновом потоке (`std::thread::spawn`).

## VPN-ключи (VpnKeyData)

Структура `VpnKeyData` хранит информацию о добавленных серверах.

```rust
pub struct VpnKeyData {
    pub name: String,
    pub protocol: String,
    pub location: String,
    pub timezone: String,
    pub url: String,
    
    // Следующие поля не сохраняются в JSON (имеют атрибут #[serde(skip)])
    #[serde(skip)] pub is_active: bool,
    #[serde(skip)] pub traffic_down: u64,
    #[serde(skip)] pub traffic_up: u64,
    #[serde(skip)] pub time_connected: u64,
    #[serde(skip)] pub ping: i32,
}
```
Поля со скипом используются исключительно в рантайме (GUI) для отображения текущей статистики. При перезапуске они сбрасываются.

## Правила маршрутизации (RoutingRule)

Структура `RoutingRule` описывает отдельное правило пользователя:
- `name`: Удобное имя (ярлык)
- `type_`: Тип цели (`"domain"`, `"ip"`, `"srs_url"`)
- `value`: Значение цели (доменное имя, CIDR подсеть, URL-ссылка на SRS)
- `action`: Действие над трафиком (`"proxy"`, `"direct"`, `"block"`)

## Безопасность настроек

Поскольку `settings.json` содержит чувствительные данные (URL-адреса с паролями, UUID и ключами шифрования), файл создается со строгими правами.

На Unix-системах используется ограничение прав на `0o600` (чтение/запись только владельцем файла). Это предотвращает доступ других пользователей системы к вашим ключам. Аналогичные меры безопасности применяются при функциях экспорта/импорта.

## Канал перезапуска ядра (Core Restart Channel)

Некоторые изменения настроек (например, переключение тумблера `tun_mode` или смена порта) требуют полного перезапуска процесса Sing-box, чтобы они вступили в силу.

Для этого в `src/settings.rs` реализован глобальный канал `core_restart_channel()`, использующий паттерн `OnceLock` и `async_channel`. Если настройка, требующая перезапуска, меняется, UI-код отправляет сигнал в этот канал, и ядро автоматически рестартует (если оно было включено).

## Системный прокси GNOME

Функция `update_system_proxy(enable: bool, http_port: u16, socks_port: u16)` модифицирует D-Bus хранилище настроек (GSettings) рабочего стола GNOME.
- Если `enable = true`, в `org.gnome.system.proxy` устанавливается режим `manual`, и прописываются порты `127.0.0.1`.
- Если `enable = false`, устанавливается режим `none`.
