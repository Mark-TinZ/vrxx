# Руководство для контрибьюторов (Contributing Guide)

Мы рады приветствовать новых разработчиков в проекте `vrxx`! Чтобы процесс разработки был комфортным для всех, пожалуйста, ознакомьтесь с нашими правилами.

## Требования к коду (Code Style)

- В проекте используется `rustfmt`. Перед коммитом всегда выполняйте `cargo fmt`.
- Мы стремимся к чистому коду. Обязательно проверяйте код линтером: `cargo clippy -- -D warnings`.
- Не используйте `unwrap()` и `expect()` в рабочем коде (за исключением тестов). Используйте `anyhow::Result` или прокидывайте ошибки наверх.
- Блокировка UI-потока (Main GTK Thread) строго запрещена. Все операции I/O и системные вызовы должны выполняться асинхронно или в фоновых потоках (`std::thread::spawn` + `glib::Sender`/`Receiver`).

## Архитектура проекта

Проект разделен на слои:
- `src/domain/` — Бизнес-логика, модели данных.
- `src/services/` — Сервисы (управление ядром, мониторинг, пинги).
- `src/ui/` — Компоненты GTK, интерфейс, обработчики событий.

Пожалуйста, не смешивайте бизнес-логику и UI. Обработчики кнопок должны вызывать методы сервисов.

## Запуск тестов

- `cargo test` запускает все Unit-тесты.
- Обязательно пишите тесты для нового функционала (особенно в `src/domain` и `src/services`).

Спасибо за ваш вклад!
