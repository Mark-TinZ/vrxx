# ТЗ 02: TUI Интерфейс на Ratatui (`vrxx tui`)

## 1. Назначение и Архитектурный Слой
- **Слой:** UI / CLI (`src/tui/`, `src/bin/vrxx-tui.rs` или подкоманда `vrxx tui`)
- **Назначение:** Предоставление консольного интерфейса управления VPN-клиентом для пользователей терминала без использования графического окружения.

## 2. Требования к реализации
1. **Интерактивный терминал на базе `ratatui` и `crossterm`:**
   - Компактный макет:
     - Верхняя панель: Статус подключения (Connected / Disconnected / Error), текущий режим (TUN / Proxy), активный сервер.
     - Центр: График входящей и исходящей скорости трафика (`ratatui::widgets::Sparkline` или `Chart`), список профилей с навигацией клавишами `Up`/`Down`.
     - Нижняя панель: Горячие клавиши (`Space` - Подключить/Отключить, `Tab` - Сменить режим TUN/Proxy, `l` - Логи, `q` - Выход из TUI).
2. **IPC Подключение:**
   - Подключается к `/run/vrxx/daemon.sock`.
   - Не препятствует параллельной работе GUI или фонового соединения.
   - Закрытие TUI (`q`) не рвет фоновое подключение VPN.

## 3. Требования из CONTRIBUTING.md
- **Разделение слоев:** TUI не содержит логики генерации конфигов или вызовов `ip route`. Вся логика запрашивается через IPC у слоя Backend/Daemon.
- **Безопасность потоков:** Терминальный цикл обработки событий `crossterm::event::read()` работает в отдельном `tokio::task` с неблокирующим рендерингом `terminal.draw()`.
- **Логирование и Ошибки:** Ошибки терминала и IPC оборачиваются в `anyhow::Result` без использования `.unwrap()`.
