# ТЗ 08: Совместимость с GNOME HIG и Кросс-десктопный Fallback (KDE/XFCE)

## 1. Назначение и Архитектурный Слой
- **Слой:** UI & Backend (`src/ui/`, `src/backend.rs`)
- **Назначение:** Полное соблюдение гайдлайнов GNOME HIG при сохранении работоспособности приложения на других рабочих столах (KDE Plasma, XFCE, Sway).

## 2. Требования к реализации
1. **Соответствие GNOME HIG (Libadwaita 1.5+):**
   - Визуальные элементы: `AdwApplicationWindow`, `AdwHeaderBar`, `AdwPreferencesPage`, `AdwPreferencesGroup`, `AdwActionRow`, `AdwSwitchRow`, `AdwStatusPage`, `AdwToast`, `AdwDialog`.
   - Адаптивность: Использование `AdwBreakpoint` для автоматического уплотнения макета на узких экранах.
   - Светлая / Темная тема: Автоматическое соответствие системной палитре через `style_manager`.
2. **Кросс-десктопный Fallback (KDE / XFCE / Sway):**
   - Определение среды через переменную `std::env::var("XDG_CURRENT_DESKTOP")`.
   - При работе в GNOME: Переключение системного прокси через GSettings `org.gnome.system.proxy`.
   - При работе в KDE/XFCE:
     - Безопасная проверка доступности схемы `org.gnome.system.proxy` перед вызовом `gio::Settings`.
     - Если схема отсутствует, вывод тоста/предупреждения с предложением переключиться в **TUN-режим** (так как TUN работает на уровне ядра Linux независимо от среды рабочего стола) или установка переменных окружения (`HTTP_PROXY`, `HTTPS_PROXY`).

## 3. Требования из CONTRIBUTING.md
- **Отсутствие крашей:** Недоступность сервиса DBus или GSettings GNOME в KDE не должна вызывать ошибку запуска или `.unwrap()` панику.
- **Главный поток UI:** Любые проверки окружения выносятся из главного потока отрисовки UI.
