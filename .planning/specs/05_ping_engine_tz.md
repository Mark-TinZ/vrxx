# ТЗ 05: Модуль Тестирования Задержки (Ping Engine: 4 Алгоритма)

## 1. Назначение и Архитектурный Слой
- **Слой:** Domain & Services (`src/services/ping.rs`)
- **Назначение:** Высокоточное измерение задержки до прокси-серверов с использованием различных алгоритмов в зависимости от настроек пользователя.

## 2. Требования к реализации
1. **Поддержка 4 алгоритмов пинга:**
   - **`ViaProxyGet`:** HTTP GET запрос к целевому URL через SOCKS5/HTTP прокси (проверяет реальное прохождение данных и HTTP-стек).
   - **`ViaProxyHead`:** HTTP HEAD запрос к целевому URL через прокси (быстрая проверка).
   - **`TcpHandshake`:** Измерение времени установления TCP 3-way handshake напрямую с `host:port` сервера.
   - **`IcmpPing`:** Отправка ICMP Echo Request пакетов к IP-адресу сервера.
2. **Конфигурируемость:**
   - Настройка выбора метода пинга в настройках GUI (`src/settings.rs`).
   - Настройка целевого URL для проверки (по умолчанию: `https://www.gstatic.com/generate_204`).
3. **Параллельное исполнение:**
   - Пинг списка профилей выполняется параллельно с использованием `tokio::spawn` и лимита одновременных задач (`futures::stream::buffer_unordered`).
   - Таймаут на каждый запрос — 3 секунды.

## 3. Требования из CONTRIBUTING.md
- **Отсутствие блокировок UI:** Результаты пинга передаются в главную цепочку GTK через `async_channel` или `glib::spawn_future_local`.
- **Безопасность типов:** Ошибки пинга (таймаут, сбой сети, ошибка прокси) не вызывают паник, а возвращают результат `PingResult::Timeout` или `PingResult::Error(String)`.
