## 2024-05-16 - Prevent Insecure Default Directory Permissions
**Vulnerability:** The codebase was widely using `std::fs::create_dir_all` to create application data directories (e.g., config, logs, autostart directories in `~/.config/vrxx/`). This relies on the system default umask, which can result in overly permissive directory permissions allowing other local users to read sensitive VPN credentials or access application logs.
**Learning:** `std::fs::create_dir_all` should not be used for sensitive configuration and log directories without careful permission setup, because the default rust implementation delegates to system defaults which are often not `0o700`.
**Prevention:** Introduce a centralized utility function (like `crate::utils::secure_create_dir_all`) that utilizes `std::fs::DirBuilder` combined with `std::os::unix::fs::DirBuilderExt` to explicitly set `builder.mode(0o700)` on Unix platforms, ensuring only the owner can read/write/execute the created directories. All new directory creation for application state must use this secure wrapper.
